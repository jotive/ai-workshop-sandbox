# Handbook — ai-workshop-sandbox

> Índice corto. Todo el contenido operativo y de referencia vive en `docs/handbook/*` y se carga bajo demanda, no en cada tarea.

- **Arquitectura** → `docs/handbook/architecture.md` (stack, estructura de carpetas, flujos de datos y lo que NO existe).
- **Convenciones** → `docs/handbook/conventions.md` (estilo de código, naming semántico, patrones aceptados, estrategia de tests).
- **Decisiones** → `docs/handbook/decisions.md` (índice rápido, una fila por ADR, link a `docs/adr/` para el detalle largo).
- **Glosario** → `docs/handbook/glossary.md` (términos del dominio de tickets usados en este repo).
- **Workflow** → `docs/handbook/workflow.md` (índice denso: entorno, checklist pre-merge, ramas, deploy, ciclo con agentes IA).
- **Desarrollo día a día** → `docs/handbook/development.md` (setup, comandos comunes).
- **Git / ramas** → `docs/handbook/git-workflow.md` (convención de ramas de este repo, commits, cuándo hacer PR).
- **Testing** → `docs/handbook/testing.md` (cómo correr tests, qué cubrir, criterio de aceptación).
- **Releases** → `docs/handbook/releases.md` (breve: este proyecto no tiene proceso de release real).
- **Errores conocidos** → `docs/handbook/errors.md` (síntoma, causa raíz, solución).
- **Agentes de IA en este repo** → `docs/handbook/ai-agents.md` (reglas específicas del ciclo research → plan → implementa → verifica con OpenSpec).

Decisiones de arquitectura con detalle largo (contexto, opciones descartadas, consecuencias): `docs/adr/` — una por archivo. `docs/handbook/decisions.md` es el índice rápido, `docs/adr/` sigue siendo la fuente de detalle.

Onboarding: `docs/onboarding.md` (cómo arranca alguien nuevo, humano o agente, en este repo).
